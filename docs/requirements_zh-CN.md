# V.35 相位测量子系统——需求规格

文档修订：v1.2
RTL 基线：v1.0（本次勘误不修改 RTL）
状态：忠实版需求已冻结并完成 RTL 验证
日期：2026-08-20

## 1. 状态定义

- **基线**：忠实版必须实现并验证。
- **实现裁决**：原系统不要求唯一处理方式，但 RTL 或软件必须选择一种确定行为。
- **候选增强**：只进入拓展版，不得改变忠实版兼容行为。
- **待确认**：仍需原代码、原器件资料或工程师补充。

## 2. 运行环境与同步

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-ENV-001 | 基线 | 内部功能逻辑仅由 50 MHz 参考时钟驱动。 |
| REQ-ENV-002 | 基线 | 支持 64 kHz 至 2.048 MHz 的 V.35 接收时钟范围。 |
| REQ-ENV-003 | 基线 | `v35_rclk` 与 `v35_data` 各自使用独立、同构的两级同步器。 |
| REQ-ENV-004 | 基线 | 第一级同步寄存器只允许连接第二级，不得进入普通逻辑。 |
| REQ-ENV-005 | 基线 | 事件检测只比较第二级同步输出与其历史样本。 |
| REQ-ENV-006 | 基线 | 接收时钟只报告上升沿；数据报告任意极性翻转。 |
| REQ-ENV-007 | 基线 | 规格只承诺离散可观测事件，不承诺恢复采样点之间被折叠的翻转。 |
| REQ-ENV-008 | 待确认 | 输入最小高低电平和最小有效跳变间隔。 |
| REQ-ENV-009 | 基线 | 同步器不提供 `sync_valid`；事件检测器用内部 `detector_armed` 令复位后的第一个样本仅建立历史基线。 |

## 3. CPU 控制的相位测量

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-FUNC-001 | 基线 | CPU 在空闲时通过 `mem13[3]` 写 `1→0` 发起检测；寄存器接口生成持续一个 50 MHz 周期的内部 `measurement_start`；未启动时不得发布新结果。 |
| REQ-FUNC-002 | 基线 | 检测窗口内每次 `rclk_rise_evt` 都建立新周期原点并把相位计数清零。 |
| REQ-FUNC-003 | 基线 | 若连续若干周期无数据翻转，每个新 `rclk_rise_evt` 仍替换旧原点并重新清零。 |
| REQ-FUNC-004 | 基线 | 在有效原点建立前出现的数据事件不得产生有效结果。 |
| REQ-FUNC-005 | 基线 | 原点建立后，第一个内部可观测 `data_toggle_evt` 锁存本周期结果。 |
| REQ-FUNC-006 | 基线 | 同一周期的后续数据活动不得覆盖已锁存结果。 |
| REQ-FUNC-007 | 基线 | CPLD 每次已启动的测量事务独立生成一个有效结果；RTL 不负责 CPU 侧的多样本平均。 |
| REQ-FUNC-008 | 基线 | `measurement_busy=1` 时，`mem13` 控制写入必须整体拒绝，不得改变控制位或内部武装状态。 |
| REQ-FUNC-009 | 基线 | 重复写 1不得重复启动；一次武装后的第一个已接受写 0只产生一个启动单拍，后续写 0不得重触发。 |

## 4. 计数语义

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-COUNT-001 | 基线 | 结果定义为 $C_{\mathrm{phase}} = n_d - n_r$。 |
| REQ-COUNT-002 | 基线 | 相邻拍事件的结果为 1。 |
| REQ-COUNT-003 | 基线 | 观测时间为 $t = C_{\mathrm{phase}} \times 20\text{ ns}$。 |
| REQ-COUNT-004 | 基线 | 相位结果宽度为 10 位。 |
| REQ-COUNT-005 | 基线 | 同拍 `rclk_rise_evt` 与 `data_toggle_evt` 以本拍为新原点并锁存结果 0。 |
| REQ-COUNT-006 | 基线 | 同拍行为必须显式编码，不得依赖非阻塞赋值的偶然旧值。 |

## 5. 结果接口与读清

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-IF-001 | 基线 | 数据捕获后置 `result_valid`，并向 CPU 提供稳定的 10 位结果。 |
| REQ-IF-002 | 基线 | CPU 读取结果时同时清除 `result_valid`。 |
| REQ-IF-003 | 基线 | CPU 读取前且未再次启动检测时，结果值和有效状态保持稳定。 |
| REQ-IF-004 | 基线 | 读清不得破坏同步输入路径。 |
| REQ-IF-005 | 基线 | 读清后允许后续周期再次产生有效结果。 |
| REQ-IF-006 | 基线 | 旧结果未读清时，若 CPU 再次启动检测，接受 `start` 的时钟沿立即清除 `result_valid`；旧结果数值可暂存但无效；新检测完成后覆盖旧数值并重新置位 `result_valid`。 |
| REQ-IF-007 | 待确认 | 原寄存器地址、总线读时序和读清脉冲生成方式。 |
| REQ-IF-008 | 基线 | CPU 应等待结束标志后再读取；正常协议下读清与新结果捕获不会同拍。 |
| REQ-IF-009 | 实现裁决 | 若读清与新结果捕获因异常输入意外同拍，新结果捕获优先，拍后 `result_valid=1`。 |
| REQ-IF-010 | 基线 | `mem13_rdata[3]` 映射控制位，`[2]` 映射 `result_valid`，`[1:0]` 映射 `phase_result[9:8]`；`mem14_rdata` 映射 `phase_result[7:0]`。 |
| REQ-IF-011 | 基线 | 在原总线读握手未确认前，顶层暴露 `cpu_read_clear` 输入，由外部总线适配层产生，不在忠实版内推测读事务。 |

## 6. CPU 裁定边界

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-CPU-001 | 基线 | CPU 将每个有效 `phase_result` 乘以 $20\text{ ns}$，换算为 $t$，并按当前 V.35 周期 $T$ 解释。 |
| REQ-CPU-002 | 基线 | 上电或频率变化后，CPU 收集 10 个有效结果并计算平均相位。 |
| REQ-CPU-003 | 基线 | 首次校准中，$0 < t < T/4$ 或 $3T/4 < t < T$ 选择下降沿，$T/4 < t < 3T/4$ 选择上升沿。 |
| REQ-CPU-004 | 基线 | 运行期以 1 s 为采样间隔取得相位结果，并以 3 个结果的平均相位执行持续校准。 |
| REQ-CPU-005 | 实现裁决 | 3 个运行期样本采用非重叠批次，每累计 3 个结果计算一次平均并重新开始累计。 |
| REQ-CPU-006 | 基线 | 持续校准按原表选择上升沿、下降沿或保持当前设置；“保持”区域不得触发切换。 |
| REQ-CPU-007 | 实现裁决 | 原资料未定义的 $`4T/12 \le t \le 5T/12`$、$`7T/12 \le t \le 8T/12`$ 及阈值等号默认保持当前设置。 |
| REQ-CPU-008 | 基线 | CPU 的多样本调度、平均和 TDMoP 采样沿配置不进入 CPLD RTL。 |
| REQ-CPU-009 | 待确认 | 采样沿选择最终由 CPU 直接写 TDMoP，还是经 CPLD 输出控制。 |
| REQ-CPU-010 | 待确认 | CPU 如何检测频率变化，以及第一个运行期样本在初始校准后何时取得。 |

## 7. 复位

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-RST-001 | 基线 | 所有相关寄存器采用 50 MHz 域同步复位。 |
| REQ-RST-002 | 基线 | 同一路径的两级同步寄存器和历史样本使用一致初值，基线为 0。 |
| REQ-RST-003 | 基线 | 复位清除测量状态、计数、结果和 `result_valid`。 |
| REQ-RST-004 | 基线 | 复位优先于正常事件处理。 |
| REQ-RST-005 | 基线 | 复位释放后，CPU 必须等待同步链与事件历史完成填充后再发起首笔检测；当前系统级基线等待 4个 `clk_50m` 周期。 |
| REQ-RST-006 | 基线 | 忠实版不保证填充过程绝无内部事件，但未启动时的任何填充事件不得产生 CPU 可见有效结果。 |

## 8. 异常与增强

| 编号 | 状态 | 需求 |
|---|---|---|
| REQ-ERR-001 | 基线 | 忠实版在无接收时钟时允许持续等待，不报告硬件超时。 |
| REQ-ERR-002 | 基线 | 忠实版在长期无数据翻转时继续逐周期更新原点，不报告硬件超时。 |
| REQ-ERR-003 | 候选增强 | 拓展版可增加无时钟和无数据翻转超时。 |
| REQ-ERR-004 | 候选增强 | 拓展版可增加计数饱和或回绕诊断。 |
| REQ-ERR-005 | 候选增强 | 拓展版可增加 `multiple_toggle`。 |
| REQ-ERR-006 | 候选增强 | 拓展版可增加 `boundary_flag`，但忠实版同拍结果仍为 0。 |

## 9. 同拍优先级

同一 50 MHz 拍内的优先级为：

1. 同步复位；
2. `start` 启动或重启检测并清除旧 `result_valid`；
3. 新结果捕获优先于 CPU 读清；正常 CPU 协议不会形成该竞争；
4. 时钟与数据同拍时，清零并锁存 0；
5. 仅数据事件时，锁存当前计数；
6. 仅时钟事件时，清零；
7. 无事件时，按状态递增计数。
