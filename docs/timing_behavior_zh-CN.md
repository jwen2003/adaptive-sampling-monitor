# V.35 相位测量子系统——逐拍时序行为

文档修订：v1.2
RTL 基线：v1.0（本次勘误不修改 RTL）
状态：忠实版逐拍行为已实现并验证
日期：2026-08-20

## 1. 文档目的

本文冻结 CPU 控制的单次相位检测事务及其逐拍行为。一次检测窗口内可跨多个接收时钟周期更新最近原点，直到捕获第一次数据翻转。

## 2. 内部信号

- `rclk_rise_evt`：同步后的 V.35 接收时钟上升沿单拍事件；
- `data_toggle_evt`：同步后的 V.35 数据翻转单拍事件；
- `mem13_write`、`mem13_wdata`：CPU 对控制寄存器的写入接口；
- `measurement_start`：寄存器接口接受 `mem13[3]` 写 `1→0` 后产生的单拍内部事件；
- `cpu_read_clear`：CPU 读取结果时形成的读清事件；
- `sync_reset`：50 MHz 域同步复位；
- `origin_valid`：已经建立至少一个有效周期原点；
- `phase_count[9:0]`：当前周期相位计数；
- `phase_result[9:0]`：锁存给 CPU 的结果；
- `result_valid`：锁存结果有效。

## 3. 概念状态

| 状态 | 含义 |
|---|---|
| `Idle` | 等待内部 `measurement_start`。 |
| `WaitRclk` | 已启动检测，尚未建立有效周期原点。 |
| `WaitData` | 已有原点，等待本周期第一次可观测数据翻转。 |
| `ResultValid` | 检测完成，结果对 CPU 可读；等待读清或再次启动。 |

`result_valid` 是 CPU 可见的结束标志。CPU 不直接驱动内部 `start`：空闲时先向 `mem13[3]` 写 1完成武装，再写 0，由寄存器接口产生持续一个 50 MHz 周期的 `measurement_start`。CPU 再次完成该序列时，即使旧结果未读清，也进入新一轮检测；接受启动的时钟沿立即清除旧 `result_valid`，新一轮完成时覆盖旧结果数值并重新置位。

## 4. 正常逐拍规则

| 当前条件 | 事件 | 动作 |
|---|---|---|
| 任意 | `sync_reset` | 清除同步历史、原点、计数、结果与有效位。 |
| 寄存器接口空闲且未武装 | 接受 `mem13[3]=1` 写入 | 置控制位并武装一次未来启动，不产生 `measurement_start`。 |
| 寄存器接口空闲且已武装 | 接受 `mem13[3]=0` 写入 | 清控制位、消耗武装并产生一个周期的 `measurement_start`。 |
| 测量忙 | 任意 `mem13` 控制写 | 整体拒绝，不改变控制位和武装状态。 |
| `Idle` | `measurement_start` | 开启检测，清除本轮原点状态和旧 `result_valid`；旧结果数值可暂存，但在新结果完成前无效。 |
| 无有效原点 | 无事件或仅数据事件 | 保持等待，不产生结果。 |
| 无有效原点 | 仅时钟事件 | 建立原点，`phase_count=0`。 |
| 无有效原点 | 时钟与数据同拍 | 建立原点并锁存结果 0。 |
| 已有原点，本周期未捕获 | 无事件 | `phase_count` 递增。 |
| 已有原点，本周期未捕获 | 仅时钟事件 | 以新周期替换旧周期，`phase_count=0`。 |
| 已有原点，本周期未捕获 | 仅数据事件 | 锁存当前 `phase_count`。 |
| 已有原点，本周期未捕获 | 时钟与数据同拍 | 以本拍为新原点，锁存结果 0。 |
| `ResultValid` | `cpu_read_clear` | 清除 `result_valid`；结果寄存器可保持原值。 |

## 5. 计数定义

设接收时钟事件出现在拍 `n_r`，本周期第一次数据事件出现在拍 `n_d`：

$$
C_{phase}=n_d-n_r
$$

$$
t=C_{phase}\times20\text{ ns}
$$

示例：

| 拍号 | 事件 | 拍后计数或结果 |
|---|---|---|
| 2 | `rclk_rise_evt` | `phase_count=0` |
| 3 | 无 | `phase_count=1` |
| 4 | 无 | `phase_count=2` |
| 5 | `data_toggle_evt` | 锁存结果 3 |

同拍时 `n_d=n_r`，结果为 0；相邻拍结果为 1。

## 6. 连续无数据翻转

假设多个接收时钟周期内数据保持不变：

| 事件序列 | 行为 |
|---|---|
| 第一个 `rclk_rise_evt` | 清零，建立原点 A。 |
| 原点 A 后无数据事件 | 逐拍递增。 |
| 下一个 `rclk_rise_evt` | 放弃 A，清零，建立原点 B。 |
| 原点 B 后仍无数据事件 | 继续逐拍递增。 |
| 某周期首次 `data_toggle_evt` | 相对最近原点锁存结果。 |

这不是超时或失败；原兼容版本没有硬件超时机制。

## 7. 结果与读清

结果捕获后：

- CPU 未再次启动时，`phase_result` 与 `result_valid` 保持到 CPU 读取；
- `cpu_read_clear` 清除 `result_valid`；
- 读清不应制造新的时钟或数据事件；
- 读清后下一个合法结果可重新置位。
- 若 `result_valid=1` 时 CPU 再次发出单拍 `start`，接受启动的时钟沿立即清除 `result_valid`；新结果完成时覆盖旧数值并重新置位；
- CPU 按正常协议等待结束标志后才读取，因此读清与新结果捕获不会同拍；
- 若异常激励使二者意外同拍，RTL 采用新结果捕获优先：写入新结果并在拍后保持 `result_valid=1`。

## 8. 同步复位

同步复位只在 `clk_50m` 上升沿生效，并优先于普通事件：

```systemverilog
always_ff @(posedge clk_50m) begin
    if (sync_reset) begin
        // 清除同步链、历史、状态、计数、结果和有效位
    end else begin
        // 正常逐拍行为
    end
end
```

复位释放后，应等待同步链和历史样本完成填充后再发起首笔检测。当前系统级基线等待 4个 `clk_50m` 周期。

事件检测器不使用 `sync_valid`。其内部 `detector_armed` 在复位后的第一个时钟拍保存 `sync_in` 作为历史基线并置位；该拍不报告事件，后续才比较相邻同步样本。若异步输入在复位期间已为高电平，两级同步器从 0填充到 1仍可能在后续形成一次内部事件；测量未启动时该事件不产生有效结果。

## 9. CPU 裁定的时序边界

CPU 每次只从 CPLD 读取一个 `phase_result`，但不立即将每个单样本转化为采样沿切换：

1. 上电或频率变化后，CPU 重复发起单次事务并收集 10 个有效结果，求平均后执行首次校准；
2. 运行期以 1 s 为采样间隔取得结果，本项目采用 3 样本非重叠批次；
3. 累计 3 个结果后求平均并执行一次持续校准，随后清空该批次；
4. 持续校准表的“保持当前设置”区域不产生切换；
5. 原资料未定义的两段空白区间和阈值等号默认保持当前设置。

上述 CPU 时间尺度不改变本文件定义的 CPLD 50 MHz 逐拍结果。“3 样本非重叠批次”是对原文“每 1 s 采样一次，采样 3 次求平均”的重建裁决；滑动窗口没有原始资料支持。

## 10. 候选增强

以下行为不进入兼容基线：

- 无接收时钟超时；
- 长期无数据翻转超时；
- 计数饱和上报；
- `boundary_flag`；
- `multiple_toggle`；
- 独立 `Error` 状态。

若拓展版采用，必须另行定义计时起点、清除条件以及与正常事件同拍时的优先级。

## 11. 验证必须覆盖的逐拍组合

1. 首个原点前的数据事件；
2. 未启动时的时钟和数据事件不产生结果；
3. 正常相邻拍结果 1；
4. 多拍结果；
5. 时钟与数据同拍结果 0；
6. 连续多个周期无数据翻转且每周期重新清零；
7. CPU 读取前且未重启时结果保持；
8. 未读旧结果时再次启动，启动拍清除 `result_valid`，新结果完成后覆盖旧数值并重新置位；
9. CPU 读清后再次捕获；
10. 异常同拍时新结果捕获优先；
11. 同步复位发生在等待、计数和结果有效阶段；
12. 复位释放后等待 4拍再启动，填充期间不产生 CPU 可见结果。

## 12. 顶层接口的逐拍边界

- `mem13_rdata` 与 `mem14_rdata` 是当前状态的连续组合映射，不表示某次总线读已经发生；
- `cpu_read_clear` 由顶层外部的真实总线适配层提供，拉高一个有效参考时钟拍后清除 `result_valid`；
- `cpu_read_clear` 不清除 `phase_result`；
- 若 `cpu_read_clear` 与新结果捕获异常同拍，新捕获结果和 `result_valid=1` 保留；
- 具体总线地址译码、读使能和握手不属于忠实版顶层。

## 13. CPU 动态响应时间

按当前调度重建，一个运行期结果约每 1 s 取得一次，三个非重叠结果形成一批，因此一次持续裁定约每 3 s 发生。候选置信门不会改变 CPLD 单次事务时序，但会改变 CPU 何时接受一批结果并切换采样沿。

定向动态场景中，快速明确相位跳变没有增加决策批次；缓慢跨越约增加 2 批，即约 6 s；带噪声跨越约增加 4 批，即约 12 s。该时间只来自当前构造轨迹与调度重建，不是产品最坏时延保证。
